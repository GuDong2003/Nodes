# 任务诊断日志

任务详情会保存时间、worker 编号、尝试轮次、执行阶段、异常类型和 HTTP 状态。
日志随 `web-data/tasks.json` 持久化，重建容器时需保留该目录挂载。
每个任务保留最近 100 条过程日志。旧任务没有采集到的异常无法补回。

任务日志只接受程序明确生成的阶段信息和已知安全错误，不复制原始 worker 输出。
未知异常仅记录类型和 HTTP 状态，不保存邮箱地址、密码、验证码、令牌、请求 URL
或完整接口响应。需要更深入诊断时，应在具体失败环节补充白名单字段。

## 单次验证

已登录且携带 CSRF 令牌时，可向 `POST /api/tasks` 提交：

```json
{"count": 1, "concurrency": 1, "max_attempts": 1}
```

`max_attempts` 只接受 1–3 的整数，未填写时保持原来的三次账号尝试。
设为 1 时，不更换邮箱重新注册，通用 HTTP 重试也限制为一次。
等待邮件和查询任务状态的轮询仍照常进行。此参数不改变代理或验证码配置。

任务失败不代表注册流程的每一步都失败；以具体阶段为准。仅有账号文件时显示
“已保存未完成账号”，完全失败时不会再声称保存了账号诊断记录。
